# 添加内置记号贡献指南

本文档面向向 ne-rewritten 仓库直接提交 Pull Request、将记号永久加入内置集合的贡献者。它描述一个内置记号从新建模块、注册、测试到提交 PR 的完整流程，以及记号定义对象各字段必须满足的契约。

本文档与运行时的"自定义记号脚本"接口（`src/assets/api.md`）是**两套不同的集成路径**：

| 维度 | 运行时上传脚本 | 仓库内置记号（本文档） |
|---|---|---|
| 语言 | 普通 JavaScript | TypeScript |
| 注册方式 | 脚本内调用 `register_notation` | 模块**只导出定义对象**，注册由 `src/main.ts` 统一完成 |
| 依赖引用 | 无 `import`，仅使用注入的三个函数 | 通过 `@/` 路径别名自由 import 共享模块 |
| 测试 | 无 | 在 `src/test/` 下附带 vitest 测试 |
| 生效方式 | 用户在面板上传 | 合并后随站点部署，所有用户可见 |

---

## 1. 最小流程

向仓库新增一个内置记号，按顺序完成以下步骤：

1. 在 `src/notations/<相关类别目录>/` 下新建 `.ts` 文件，定义表达式类型与记号定义对象并导出。
2. 若需要新的分组类别，在同目录的 `categories.ts` 中导出类别定义对象。
3. 在 `src/main.ts` 顶部 `import` 该记号与类别，并在文件中部的注册区按依赖顺序调用 `register_category(...)` 与 `register_notation(...)`。
4. 在 `src/test/` 下新建对应的 vitest 测试文件。
5. 本地运行 `npm run typecheck` 与 `npm run build`，确保类型检查与构建通过。
6. 运行 `npm run dev`，在浏览器中人工展开若干典型表达式，核对基本列正确性。
7. 提交 PR。

环境要求：Node.js 24（与 CI 一致）。依赖安装使用 `npm ci` 或 `npm install`。

## 2. 记号模块的文件结构

一个记号模块通常由三部分组成：表达式类型、辅助函数、记号定义对象。以 `src/notations/OCN/LMN.ts` 为典型骨架：

```ts
import { deepcopy } from '@/utils.ts';
import { NotationDefinition } from '@/notation-definition.ts';

// (1) 表达式类型: 由贡献者自定义, 可以是数字、数组、元组或普通对象
export type PrimExpr = [true, number, Expr];
export type SumExpr = [false, Expr, Expr];
export type Expr = 0 | PrimExpr | SumExpr;

// (2) 辅助函数: 凡是测试需要用到的函数一律 export
export function from_display(str: string): Expr { /* ... */ }
export function LMN_compare(x: Expr, y: Expr): number { /* ... */ }
export function LMN_is_limit(x: Expr): boolean { /* ... */ }

// 模块级缓存: FS 会以递增 index 对同一表达式反复调用, 按显示字符串缓存基本列项
const data: Record<string, Expr[]> = {};

// (3) 记号定义对象: 导出常量, 不在本模块内调用 register_notation
export const LMN: NotationDefinition<Expr> = {
    id: 'lmn',
    name: 'lifting M-notation',
    simple_name: 'LMN',
    category_id: 'category-ocn',
    display: { /* ... */ },
    is_limit: LMN_is_limit,
    compare: LMN_compare,
    FS: (x: Expr, index: number) => { /* 带缓存的基本列 */ },
    init: () => [[true, Infinity] as unknown as Expr, [true, 0, 0], 0],
};
```

约定：

- 模块**只导出定义对象与必要的辅助函数**，绝不自行调用 `register_notation` / `register_category`。注册入口唯一地在 `src/main.ts`。
- 表达式类型应显式声明，不要像历史模块那样一律使用 `any`；显式类型能让 `vue-tsc` 在实现字段契约时帮你查错。
- 辅助函数若可能被测试或其他记号复用，一律 `export`。
- 跨模块引用共享代码时使用 `@/` 路径别名（`@/` 指向 `src/`），不要使用相对路径向上回溯。常用共享模块：
  - `@/notation-definition.ts`：`NotationDefinition`、`NotationCategoryDefinition`、`resolve_display` 等类型与工具。
  - `@/core/registry.ts`：仅 `main.ts` 引用；记号模块不需要。
  - `@/notations/draw_mountain_diagram.ts`：`draw_mountain_diagram` 函数及 `MountainNode` / `MountainShape` / `MountainLayoutOptions` 类型。
  - `@/notations/mountain_view.ts`：`MountainViewSource` 类型与 `build_mountain_view`。
  - `@/notations/notation_utils.ts`：序列类记号的 FS 变体通用实现（`Y_FS_variants` 等）。
  - `@/utils.ts`：`deepcopy`、`Comparator` 等通用工具。

## 3. `NotationDefinition` 字段契约

类型定义见 `src/notation-definition.ts`。各字段语义如下。

### 3.1 基础信息

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `id` | `string` | 是 | 全仓库唯一，不得与任何记号或类别重复。提交前在 `src/` 下全局搜索该 id 确认无冲突。 |
| `name` | `string` | 是 | 记号全称。 |
| `simple_name` | `string` | 否 | 简称，缺省同 `name`。 |
| `description` | `string \| string[]` | 否 | 显示在记号树下方的说明文字。 |
| `category_id` | `string` | 否 | 所属类别 id。引用的类别必须在 `main.ts` 中先于本记号注册。省略时记号出现在导航栏顶层。 |
| `credit_text_id` | `string` | 否 | 署名文案的 i18n 键，定义于 `src/composables/use_i18n.ts`；需要新署名时同时在该文件添加翻译。 |

### 3.2 展示：`display`

```ts
display: NotationDisplaySpec<Expr>;
```

其类型为函数或对象二选一：

```ts
type NotationDisplay<T> = (a: T) => string;

type NotationDisplaySpec<T> =
    | NotationDisplay<T>
    | {
          plain: NotationDisplay<T>;
          html?: NotationDisplay<T>;
          latex?: NotationDisplay<T>;
          from_display?: (str: string) => T;
      };
```

- `plain`：纯文本视图，必填。
- `html`：HTML 视图，省略时退化为 `plain`。可使用 `<sub>` / `<sup>` 表达上下标。
- `latex`：LaTeX 视图，省略时由 `html` 输出自动转换。自动转换仅识别 `<sub>` / `<sup>`（含嵌套），并转义 `\ { } ^ _` 与 `ω Ω ψ`；复杂公式应自行提供。
- `from_display`：`plain` 的逆函数。**内置记号应提供该函数**——表格导入导出、初始表达式变体、以及测试用例都依赖它。它必须：
  1. 对任意表达式 `a`，满足 `from_display(plain(a))` 在 `compare` 意义下等于 `a`；
  2. 对无法识别的输入抛出带明确信息的异常，不得静默返回错误结果（参考 `LMN.ts` 中 `throw new Error('illegal input string: ' + str)`）。

### 3.3 等价表示：`display_equiv`

```ts
display_equiv?: Record<string, NotationDisplaySpec<Expr>>;
```

用于同一表达式的多种表示法（如 LMN 的 `plain` 与 `sup` 两种写法）。键为等价表示 id，值与 `display` 同型。若需要在导航中显示等价表示的名称，可在对象中加 `name: { id: '...' }`（i18n 键）。

### 3.4 初始表达式：`init`

```ts
init: () => Expr[];
```

返回记号树默认根节点列表。必须满足：

1. 按 `compare` 严格递减：相邻两项 `prev > next`。
2. 首项为该记号的最大表达式（通常是极限元）。
3. 末项习惯上为零（最小元）。

该列表同时被标准性检查使用，因此顺序错误会导致"标准性"判断异常。

### 3.5 核心算法：`compare` / `is_limit` / `FS`

这三个字段是记号的数学核心，必须严格满足下列契约。展开器在 `src/core/expander.ts` 中的调用方式决定了这些约束：

**`compare(a, b): number`**

在全部表达式上定义一个全序：`> 0` 表示 `a > b`，`= 0` 表示相等，`< 0` 表示 `a < b`。必须自反、反对称、可传递。展开、分析、标准性检查、表格导入校验全部以它为唯一大小依据。

**`is_limit(a): boolean`**

当 `a` 所表示的序数是极限序数时返回 `true`，是后继序数时返回 `false`。它判断的是序数本身的性质，不是"是否为记号最大元"。

**`FS(a, index): Expr`**

- 当 `is_limit(a)` 为真：运行环境以 `index = 0, 1, 2, ...` 依次调用，`FS(a, index)` 必须返回 `a` 的基本列第 `index` 项，各项按 `compare` 严格递减。
- 当 `is_limit(a)` 为假（后继序数）：运行环境**仅以 `index = 0` 调用一次**，且结果必须严格小于 `a`（即直接前继）；否则该节点被视为不可展开。
- 当 `a` 为最小元（零）：不可展开，`FS(a, 0)` 返回值无关紧要。

展开器展开一个极限节点时，从 `index = 0` 起递增调用 `FS(a, index)`，直到结果严格大于其兄弟节点边界为止。若连续超过阈值（默认 10 次，对应设置项 `max_find_fs`）仍未越过边界，展开器中断并提示"基本列实现有误"。因此基本列必须保证：对任意极限 `a` 与边界 `bound < a`，存在有限下标使 `FS(a, index) > bound`。

性能惯例：由于同一 `a` 会被以递增 `index` 反复调用，基本列通常用模块级 `Record<string, Expr[]>` 按 `plain(a)` 字符串缓存（参考 `LMN.ts`、`TON_main.ts`）。这不是契约，但属于本仓库的通用做法。

### 3.6 展开变体

```ts
FS_alter?: (a: Expr, index: number) => Expr;   // 长/替代展开
FS_short?: (a: Expr, index: number) => Expr;    // lnz-1 展开
FS_equiv?: Record<string, (a: Expr, index: number) => Expr>;
```

- `FS` 必填；后三者可选。
- 缺省变体选择规则：存在 `FS_short` 时默认使用它，否则使用 `FS`。
- 若记号属于序列类（数组表达式），可复用 `@/notations/notation_utils.ts` 中的 `Y_FS_variants` 等通用实现，避免手写三套变体。

### 3.7 图表（可选）

```ts
draw_diagram?: DiagramControl<Expr, any>;
mountain_view?: (expr: Expr, data: any) => MountainViewSource | undefined;
```

二者描述同一份几何结构，应共用一个构造函数。典型写法（参考 `BM.ts`、`Omega_MN.ts`）：

```ts
import { draw_mountain_diagram, type MountainShape } from '@/notations/draw_mountain_diagram.ts';
import type { MountainViewSource } from '@/notations/mountain_view.ts';

function build_source(expr: Expr): MountainViewSource<...> {
    return { shape: [...], layout: {...} };
}

export const MyNotation: NotationDefinition<Expr> = {
    // ...
    mountain_view: (expr) => build_source(expr),
    draw_diagram: {
        default_data: { invert_vertical: false },
        draw_diagram: (expr, data) =>
            draw_mountain_diagram(build_source(expr).shape, build_source(expr).layout, {
                invert_vertical: data.invert_vertical,
            }),
    },
};
```

`MountainShape` / `MountainLayoutOptions` 等类型的字段语义见 `src/notations/draw_mountain_diagram.ts` 与 `src/assets/api.md` 第 4 节。约定：

- `shape` 中出现的行高向量才会被绘制；虚拟行不要放入。
- 同一列内两个节点不得落在同一行。
- HTML 表格版固定按行标小者在上绘制，不响应 `invert_vertical`。

### 3.8 调试字段

```ts
debug?: Record<string, any>;
debug_verification?: (expr: Expr) => boolean | Record<string, (expr: Expr) => boolean>;
```

**内置记号不应携带这两个字段**。它们服务于用户上传脚本的运行时调试；内置记号的正确性应由 `src/test/` 下的测试保证。

## 4. 类别定义与注册

### 4.1 类别模块

在记号所属目录下的 `categories.ts` 中导出类别定义：

```ts
import { NotationCategoryDefinition } from '@/notation-definition.ts';

export const category_xxx: NotationCategoryDefinition = {
    id: 'category-xxx',
    name: 'Some Notation Family',
    simple_name: 'XXX',
    // parent_id: 'category-parent',   // 可选
    // generator: { start: 1, initial: 3, create: (n) => ... },  // 可选: 记号族生成器
};
```

若新记号属于既有类别，直接在该类别的 `category_id` 字段引用其 id 即可，无需新建类别。

### 4.2 在 `main.ts` 注册

注册分两步，均在 `src/main.ts` 完成：

1. 顶部 import 区：
   ```ts
   import { MyNotation } from '@/notations/MyCat/MyNotation.ts';
   import { category_mycat } from '@/notations/MyCat/categories.ts';
   ```
2. 文件中部的注册区（约第 183 行起），按依赖顺序插入：
   ```ts
   register_category(category_mycat);
   register_notation(MyNotation);
   ```

顺序要求：**先注册类别，再注册引用该类别的记号**。父类别先于子类别。注册区目前按记号族大致分组排列，新记号应插入与其相近的分组中，避免打乱既有顺序。

注意：`register_notation` 不允许在带 `generator` 的类别下直接注册；该类别的成员必须由 `generator.create(n)` 产出。普通记号不要使用 `generator`。

## 5. 测试

测试文件放在 `src/test/` 下，命名为 `<记号名>.test.ts`，使用 vitest：

```ts
import { describe, expect, it } from 'vitest';
import { MyNotation, from_display, display } from '@/notations/MyCat/MyNotation.ts';

describe('display', () => {
    it('极限', () => {
        expect(display(/* ... */)).toBe('...');
    });
});

describe('from_display', () => {
    it('标准用例', () => {
        expect(from_display('...')).toEqual(/* ... */);
    });
    it('非法输入', () => {
        expect(() => from_display('bad')).toThrow();
    });
});

describe('FS', () => {
    it('极限展开', () => {
        expect(display(MyNotation.FS(from_display('...'), 0))).toBe('...');
    });
    it('后继展开', () => {
        expect(display(MyNotation.FS(from_display('...'), 0))).toBe('...');
    });
});
```

测试应至少覆盖：

- `plain` 视图在典型表达式、空表达式、极限元上的输出；
- `from_display` 在典型输入与非法输入上的行为（非法输入必须抛错）；
- `FS` 在极限元、后继元、最小元上的典型步骤。

运行测试：`npx vitest run`。仓库 CI 目前只执行 `npm run build`（内含 `vue-tsc -b` 类型检查），不自动运行 vitest；但附带测试是本仓库的合并惯例，PR 描述中应说明覆盖了哪些用例。

代码格式：仓库根目录有 `.prettierrc`，提交前建议对新增文件运行 `npx prettier --write`。

## 7. PR 自查清单

提交前逐项确认：

- [ ] 新记号的 `id` 在 `src/` 下全局唯一。
- [ ] `category_id` 引用的类别已在 `main.ts` 中先于本记号注册。
- [ ] `init()` 返回的数组严格递减，首项为极限元。
- [ ] `compare` 满足全序；`is_limit` 正确区分极限/后继；后继节点的 `FS(a, 0)` 严格小于 `a`。

- [ ] `src/test/` 下附带测试，`npx vitest run` 通过。

- [ ] 未携带 `debug` / `debug_verification` 字段。

## 附录 B. 最小记号模块骨架

```ts
import { NotationDefinition } from '@/notation-definition.ts';

// 表达式载体类型
export type Expr = number | 'limit';

export function display(e: Expr): string {
    return e === 'limit' ? 'ω' : String(e);
}

export function from_display(s: string): Expr {
    if (s === 'ω') return 'limit';
    if (/^\d+$/.test(s)) return Number(s);
    throw new Error('illegal input: ' + s);
}

export function compare(a: Expr, b: Expr): number {
    if (a === b) return 0;
    if (a === 'limit') return 1;
    if (b === 'limit') return -1;
    return a > b ? 1 : -1;
}

export function is_limit(e: Expr): boolean {
    return e === 'limit';
}

export const NaturalNumbers: NotationDefinition<Expr> = {
    id: 'natural-numbers',
    name: 'Natural numbers',
    simple_name: 'N',
    category_id: 'category-misc',
    display: { plain: display, from_display },
    init: () => ['limit' as Expr, 0],
    is_limit,
    compare,
    FS: (e: Expr, i: number): Expr => (e === 'limit' ? i : e > 0 ? e - 1 : 0),
};
```
